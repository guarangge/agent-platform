# 表功能说明

## 1. conversations

### 1.1 表职责

`conversations` 用于存储会话主记录和最近一次运行态信息，不保存完整消息历史。

这张表主要解决 4 件事：

1. 标识当前会话属于哪个用户
2. 固化当前会话绑定的 Agent / Prompt 运行快照
3. 记录会话列表展示所需的标题、状态、最近时间、最近摘要
4. 作为 `messages`、`tasks` 等运行数据的归属主表

### 1.2 典型流程

1. 新建会话时
   系统会读取当前选择的 Agent 及其关联 Prompt 配置，把关键快照写入 `conversations`

2. 首次发送消息时
   如果 `title` 为空，则使用本次用户消息内容截取生成标题并回写

3. 用户发送消息进入执行时
   会话状态从 `pending` 更新为 `processing`

4. 执行成功、失败或进入审批等待时
   会继续更新 `status`、`last_message_at`、`last_message_preview`

### 1.3 字段说明

| 字段名 | 说明 |
| --- | --- |
| id | 主键 ID |
| conversation_code | 会话编码，业务唯一标识 |
| user_id | 会话所属用户 ID |
| agent_id | 当前会话绑定的 Agent ID |
| agent_code | Agent 编码快照 |
| agent_name | Agent 名称快照 |
| default_model | 默认模型快照 |
| default_prompt_id | 默认 Prompt ID 快照 |
| default_prompt_name | 默认 Prompt 名称快照 |
| title | 会话标题。当前实现中，通常由首次发送的用户消息截取生成 |
| status | 会话最近一次主流程状态，当前包括 `pending`、`processing`、`waiting_approval`、`success`、`failed` |
| last_message_at | 最近一次会话状态更新的时间，不应简单理解为用户发送时间 |
| last_message_preview | 最近一次状态更新时写入的摘要信息，可能是用户消息摘要、助手返回摘要、失败提示或等待审批提示 |
| metadata | 会话扩展信息，存储附加业务属性 JSON |
| remark | 备注 |
| created_at | 创建时间 |
| created_by | 创建人 |
| updated_at | 更新时间 |
| updated_by | 更新人 |
| is_deleted | 逻辑删除标记 |

### 1.4 与其他表的关系

1. `conversations` 与 `messages` 是一对多，`messages.conversation_id` 指向 `conversations.id`
2. `conversations` 与 `tasks` 是一对多，`tasks.conversation_id` 指向 `conversations.id`
3. `conversations` 与 `conversation_memories` 当前是一对一

### 1.5 使用边界

1. 不要把完整消息历史放在 `conversations`，完整内容应查看 `messages`
2. 不要把任务执行步骤放在 `conversations`，执行步骤应查看 `task_steps`
3. `status` 表示最近一次运行态，不表示永久业务状态
4. `last_message_preview` 用于列表摘要展示，不等同于完整原文

### 1.6 实现总结

1. 新建对话窗口时，会读取当前选择的 Agent 信息及其关联的 Prompt 信息，固化到 `conversations` 表中的快照字段。
2. 发送消息时，会先判断当前会话标题是否为空；如果为空，则根据本次用户消息内容截取生成标题并更新。
3. `last_message_at` 不应简单理解为发送时间，而应理解为会话最近一次状态更新的时间。
4. 会话状态会在 `pending`、`processing`、`success`、`failed`、`waiting_approval` 之间流转。
5. `last_message_preview` 表示最近一次状态更新时写入的摘要信息，可能是用户消息摘要、助手返回摘要、失败提示或等待审批提示。
6. `conversations` 不再保存默认 Workflow；Workflow 是否执行以及执行哪个 Workflow，统一在任务的 `ExecutionDecision` 阶段决定。

## 2. messages

### 2.1 表职责

`messages` 用于记录会话中的历史消息明细，是对话历史记录表。

这张表主要解决 4 件事：

1. 记录用户消息原文
2. 记录助手回复内容
3. 按会话维度维护消息顺序
4. 为会话历史展示和后续上下文构建提供原始消息数据

### 2.2 典型流程

1. 用户发送消息时
   先写入一条 `message_type = user` 的消息记录

2. 助手返回结果时
   再写入一条 `message_type = assistant` 的消息记录

3. 同一会话内
   每条消息都会按 `sequence_no` 递增，表示在当前会话中的先后顺序

### 2.3 字段说明

| 字段名 | 说明 |
| --- | --- |
| id | 主键 ID |
| conversation_id | 所属会话 ID |
| message_type | 消息类型，当前主要包括 `user`、`assistant`，预留 `system` |
| sequence_no | 会话内顺序号 |
| content | 消息内容原文 |
| response_status | 响应状态 |
| error_message | 失败原因 |
| metadata | 扩展信息 |
| created_at | 创建时间 |
| created_by | 创建人 |
| updated_at | 更新时间 |
| updated_by | 更新人 |
| is_deleted | 逻辑删除标记 |

### 2.4 与其他表的关系

1. `messages` 与 `conversations` 是多对一，`messages.conversation_id` 指向 `conversations.id`
2. 用户消息可触发一条 `tasks`，`tasks.message_id` 指向触发任务的那条用户消息

### 2.5 使用边界

1. `messages` 存的是完整历史消息明细，不负责存会话级最近状态
2. 会话标题、最近摘要、最近活动时间应查看 `conversations`
3. 任务执行状态和执行步骤不在 `messages` 中维护，应查看 `tasks`、`task_steps`

### 2.6 实现总结

1. `messages` 表用于记录会话中的历史消息明细，包括用户消息、助手回复及预留的系统消息，是对话历史记录表。
2. 发送消息时，会先插入一条当前用户消息。
3. 当前最小闭环中，后续还会插入一条助手响应消息。
