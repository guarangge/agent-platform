# 多 Agent 协作流程

## 1. 结论

本项目采用“主控 Agent + 专业 Agent”协作模式。

角色分工：

1. `主控Agent`
2. `产品Agent`
3. `DBAgent`
4. `开发Agent`
5. `测试Agent`

核心原则：

1. 总计划由 `主控Agent` 制定
2. 专业 Agent 只负责本角色范围内的分计划和产出
3. 不允许多个 Agent 同时修改同一批文件
4. 所有角色必须遵守项目根目录 `AGENTS.md`
5. 所有 Git 提交信息统一使用中文
6. 用户说“提交”时，默认理解为需要提交并推送远端，而不只是本地 commit
7. 每次开发任务结束后，必须检查并更新项目计划文档
8. 所有涉及表设计、字段、索引、关系、状态规则的修改，必须同步更新 `docs/数据库设计.md`

---

## 2. 角色职责

### 2.1 主控Agent

负责：

1. 理解任务目标
2. 制定总计划
3. 拆分任务给各专业 Agent
4. 控制串行和并行顺序
5. 汇总各 Agent 结果
6. 处理冲突和裁决边界问题
7. 推动最终代码落地和结果交付
8. 每次任务完成后更新计划状态

### 2.2 产品Agent

负责：

1. 需求梳理
2. 功能清单
3. 页面原型说明
4. 业务流程说明
5. 验收标准

### 2.3 DBAgent

负责：

1. 数据库设计
2. 字段说明
3. 索引建议
4. SQL 脚本建议
5. 数据约束与一致性建议
6. 任何表设计调整都必须同步更新 `docs/数据库设计.md`

### 2.4 开发Agent

负责：

1. 技术方案细化
2. 接口实现
3. 前后端代码落地
4. 联调与验证方式整理

### 2.5 测试Agent

负责：

1. 测试计划
2. 测试点设计
3. 风险点识别
4. 回归验证
5. 缺陷列表输出

---

## 3. 计划职责

### 3.1 总计划

总计划必须由 `主控Agent` 负责。

总计划内容包括：

1. 阶段目标
2. 模块顺序
3. 里程碑
4. 串行与并行安排
5. 依赖关系
6. 风险与阻塞项
7. 当前完成状态

### 3.2 分计划

分计划由各专业 Agent 负责。

分计划内容包括：

1. 本角色任务清单
2. 输入输出
3. 依赖条件
4. 验证方式

规则：

1. `产品Agent` 不负责总排期
2. `DBAgent` 不负责总排期
3. `开发Agent` 不负责总排期
4. `测试Agent` 不负责总排期
5. 专业 Agent 只提供本角色视角的建议，由 `主控Agent` 汇总拍板
6. 每次任务完成后由 `主控Agent` 核对计划是否需要更新

---

## 4. 推荐执行顺序

推荐流程如下：

1. `主控Agent` 制定总计划
2. `产品Agent` 输出需求清单、原型说明、验收标准
3. `DBAgent` 根据需求输出表设计和 SQL 建议
4. `开发Agent` 基于稳定需求和 DB 设计开始实现
5. `测试Agent` 基于实现结果输出测试点和回归结论
6. `主控Agent` 汇总结果并决定下一轮动作

---

## 5. 串行与并行建议

### 5.1 适合串行

1. 需求不稳定时，不要先写代码
2. 表结构未稳定时，不要大规模开始后端实现
3. 接口未基本确定时，不要开始大范围前端对接
4. 代码未稳定时，不要做最终回归结论

### 5.2 适合并行

1. `产品Agent` 和 `DBAgent` 可在早期做局部并行讨论
2. `开发Agent` 可在需求稳定后与 `测试Agent` 提前沟通测试点
3. 前端和后端可在接口清单稳定后并行开发

---

## 6. 文件归档建议

建议输出目录：

```text
docs
├── collaboration
├── requirements
├── prototype
├── db
├── design
└── test
```

建议归档：

1. 需求与验收标准放 `docs/requirements`
2. 原型说明放 `docs/prototype`
3. 数据库设计放 `docs/db`
4. 技术设计放 `docs/design`
5. 测试方案与缺陷清单放 `docs/test`

---

## 7. 协作禁忌

1. 不要让多个 Agent 同时改同一批代码文件
2. 不要让 `产品Agent` 直接决定技术实现
3. 不要让 `DBAgent` 主导业务需求
4. 不要让 `测试Agent` 只给空泛结论
5. 不要让专业 Agent 绕过 `主控Agent` 直接改总计划
6. 不要长期保留没有明确任务的 `worker`
7. 不要让多个 `worker` 在没有边界说明的情况下并行开发

---

## 8. Worker 使用规则

1. `worker` 只在需要并行处理独立子任务时启用
2. 启用前必须明确任务目标、负责文件范围、输入和输出
3. 一个批次内优先保持 1 到 3 个活跃 `worker`，避免过多并行
4. 同一批代码文件只允许一个 `worker` 负责写入
5. 当前批次任务完成后，`worker` 应立即关闭
6. 只有确定马上复用时，才允许短暂保留已完成的 `worker`

---

## 9. 一句话原则

`主控Agent` 负责总计划与裁决，专业 Agent 负责本角色产出。
