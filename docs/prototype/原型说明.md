# 通用 Agent 平台 MVP 原型说明

## 1. 结论

本次 MVP 原型范围聚焦两个后端服务对应的最小前端闭环：

1. `registry-center` 认证登录入口
2. `registry-center` 的 Agent / Tool / Workflow / Prompt / 权限 管理入口
3. `agent-core` 会话页

MVP 阶段目标不是做完整平台，而是先让用户能：

1. 登录系统
2. 进入统一后台
3. 看到并管理核心资源入口
4. 进入会话页发起一次最小 Agent 对话

原型设计原则：

1. 统一一个管理后台，不拆多个前端站点
2. 首页先承担导航和状态概览，不追求复杂大屏
3. 资源管理页先满足“可新增、可查看、可编辑、可启停/发布”的基础操作
4. 会话页先满足“创建会话、发送消息、查看响应”的最小闭环

---

## 2. MVP 页面清单

本次建议页面共 9 个：

1. 登录页
2. 首页 Dashboard
3. Agent 管理页
4. Tool 管理页
5. Workflow 管理页
6. Prompt 管理页
7. 权限管理页
8. 会话页
9. 个人信息 / 退出入口

说明：

1. `个人信息` 可先不做独立复杂页面，MVP 可放在右上角下拉面板
2. 若前端实现阶段需要简化，也可以先保留 7 个页面，把个人信息收敛成弹层

---

## 3. 整体导航结构

建议后台采用左侧菜单 + 顶部用户区的结构。

左侧菜单建议：

1. `首页`
2. `注册中心`
3. `Agent 管理`
4. `Tool 管理`
5. `Workflow 管理`
6. `Prompt 管理`
7. `权限管理`
8. `执行中心`
9. `会话页`

顶部区域建议：

1. 系统名称：`通用 Agent 平台`
2. 当前登录用户
3. 当前环境标识：如 `DEV`
4. 退出登录

说明：

1. `注册中心`、`执行中心` 可以先只做文字分组，不一定必须有点击页
2. 真正有内容的核心页面仍是 Agent / Tool / Workflow / Prompt / 权限 / 会话

---

## 4. 页面原型说明

## 4.1 登录页

### 4.1.1 页面目标

让平台管理员或运营用户进入统一后台。

### 4.1.2 主要模块区块

1. 左侧品牌说明区
2. 右侧登录表单区
3. 页脚环境说明区

### 4.1.3 主要表单项建议

1. `username`
2. `password`
3. `rememberMe`

可选项：

1. 环境标识展示
2. 登录说明文案

### 4.1.4 关键按钮和操作说明

1. `登录`
作用：提交账号密码，登录成功后进入首页

2. `重置`
作用：清空当前输入项

### 4.1.5 页面交互流程

1. 用户进入登录页
2. 输入用户名和密码
3. 点击 `登录`
4. 登录成功后跳转到首页 Dashboard
5. 登录失败时，在表单区域展示错误提示

### 4.1.6 验收标准

1. 未登录用户访问后台受保护页面时，应跳转登录页
2. 输入合法账号密码后可以进入系统
3. 账号或密码错误时有明确提示
4. 登录成功后能正确保存登录态
5. 点击退出后登录态清除，再访问受保护页面需要重新登录

---

## 4.2 首页 Dashboard

### 4.2.1 页面目标

提供统一入口和最小状态概览，让用户快速进入注册中心和执行中心核心页面。

### 4.2.2 主要模块区块

1. 顶部欢迎区
2. 快捷入口卡片区
3. 平台概览卡片区
4. 最近会话区

### 4.2.3 主要展示项建议

快捷入口卡片：

1. `Agent 管理`
2. `Tool 管理`
3. `Workflow 管理`
4. `Prompt 管理`
5. `权限管理`
6. `会话页`

平台概览卡片建议展示：

1. Agent 总数
2. Tool 总数
3. Workflow 总数
4. Prompt 总数
5. 用户总数
6. 角色总数

最近会话区建议展示：

1. 最近进入的会话标题
2. 关联 Agent
3. 最近更新时间

### 4.2.4 关键按钮和操作说明

1. `进入管理`
作用：从快捷卡片进入对应页面

2. `新建 Agent`
作用：跳转 Agent 管理页并打开新增流程

3. `开始会话`
作用：进入会话页；若未带入 Agent，则先选择 Agent 再创建会话

### 4.2.5 页面交互流程

1. 登录成功后默认进入首页
2. 用户通过快捷入口进入具体管理页
3. 用户通过概览卡片感知系统当前资源数量
4. 用户通过最近会话快速回到最近使用的会话

### 4.2.6 验收标准

1. 首页能正确展示核心入口
2. 首页能跳转到 Agent / Tool / Workflow / Prompt / 权限 / 会话页
3. 概览数据无数据时也能正常展示空状态
4. 页面布局在常见桌面分辨率下不混乱

---

## 4.3 Agent 管理页

### 4.3.1 页面目标

管理 Agent 的基础定义和启停状态，为后续会话执行提供可选 Agent。

### 4.3.2 主要模块区块

1. 查询筛选区
2. 列表表格区
3. 新增 / 编辑抽屉或弹窗
4. 详情抽屉

### 4.3.3 查询条件建议

1. `agentName`
2. `agentCode`
3. `status`
4. `version`

### 4.3.4 列表字段建议

1. Agent 名称
2. Agent 编码
3. 描述
4. 版本
5. 状态
6. 默认模型或运行模式摘要
7. 更新时间
8. 操作列

### 4.3.5 新增 / 编辑表单项建议

1. `agentName`
2. `agentCode`
3. `description`
4. `status`
5. `defaultModel`
6. `defaultPrompt`
7. `workflowCode`
8. `toolScope`
9. `remarks`

说明：

1. `defaultPrompt` 先支持选择已有 Prompt
2. `workflowCode` 先支持选择已有 Workflow
3. `toolScope` 先支持多选 Tool 或选择“继承默认范围”

### 4.3.6 关键按钮和操作说明

1. `新建 Agent`
作用：打开新增表单

2. `查看`
作用：查看 Agent 基本信息和关联配置摘要

3. `编辑`
作用：修改 Agent 基本定义

4. `启用`
作用：把 Agent 状态改为可用

5. `停用`
作用：把 Agent 状态改为不可用

6. `进入会话`
作用：跳转会话页，并默认带上当前 Agent

### 4.3.7 页面交互流程

1. 用户进入 Agent 管理页
2. 通过筛选条件查询目标 Agent
3. 点击 `新建 Agent` 完成创建
4. 在列表中查看、编辑、启停 Agent
5. 选择某个 Agent 后，点击 `进入会话` 去执行中心体验

### 4.3.8 验收标准

1. 可以新增、查看、编辑 Agent
2. Agent 列表支持基础筛选和分页
3. Agent 状态可切换且切换结果可见
4. 可从 Agent 管理页跳转到会话页
5. 表单必填项校验明确，校验失败有提示

---

## 4.5 Workflow 管理页

### 4.5.1 页面目标

管理 Workflow 定义，为 Agent 提供可复用执行流程。

### 4.5.2 页面定位说明

MVP 阶段重点是“定义入口可管理”，不是完整低代码编排器。  
因此第一版建议采用“列表 + 基础配置表单 + 节点摘要”的方式，而不是复杂拖拽画布。

### 4.5.3 主要模块区块

1. 查询筛选区
2. 列表表格区
3. 新增 / 编辑抽屉或弹窗
4. 节点摘要区
5. 详情抽屉

### 4.5.4 查询条件建议

1. `workflowName`
2. `workflowCode`
3. `status`
4. `version`

### 4.5.5 列表字段建议

1. Workflow 名称
2. Workflow 编码
3. 描述
4. 版本
5. 节点数
6. 状态
7. 更新时间
8. 操作列

### 4.5.6 新增 / 编辑表单项建议

1. `workflowName`
2. `workflowCode`
3. `description`
4. `version`
5. `status`
6. `triggerMode`
7. `nodeSummary`
8. `remarks`

节点摘要建议支持：

1. 节点名称
2. 节点类型
3. 关联 Tool
4. 顺序说明
5. 分支说明

说明：

1. MVP 阶段节点类型先以 `tool` 为主
2. 同时在界面文案和表单结构中预留 `condition`、`approval`、`start`、`end`
3. 节点摘要先支持表格录入或文本结构化录入，不强求拖拽

### 4.5.7 关键按钮和操作说明

1. `新建 Workflow`
作用：创建新的流程定义

2. `查看`
作用：查看 Workflow 基本信息和节点摘要

3. `编辑`
作用：修改 Workflow 配置

4. `发布`
作用：将当前版本标记为可用版本

5. `停用`
作用：将 Workflow 标记为不可用

### 4.5.8 页面交互流程

1. 用户进入 Workflow 管理页
2. 通过列表查找已有 Workflow
3. 点击 `新建 Workflow` 录入基本信息和节点摘要
4. 保存后可继续编辑
5. 当流程定义满足要求时，点击 `发布`

### 4.5.9 验收标准

1. 可以新增、查看、编辑 Workflow
2. Workflow 列表支持基础筛选和分页
3. 可以看到节点摘要，不要求复杂拖拽
4. 可以执行 `发布` 或 `停用` 操作
5. 节点信息至少能表达顺序、节点类型、关联 Tool

## 4.7 权限管理页

### 4.7.1 页面目标

提供最小可用的权限配置入口，先满足用户、角色、用户绑定角色、角色绑定 Agent 的基础授权关系维护。

MVP 结构约定：

1. 权限管理页一级结构只保留 `用户管理` 和 `角色管理`
2. `绑定角色` 在用户详情中完成
3. `绑定 Agent` 在角色详情中完成
4. 不再单独把“用户绑定角色”“角色绑定 Agent”做成同级主视图

### 4.7.2 主要模块区块

1. 顶部页签切换区
2. 主列表区
3. 详情抽屉或侧栏
4. 绑定操作区

### 4.7.3 主要展示与表单项建议

页签建议：

1. `用户管理`
2. `角色管理`

用户列表建议展示：

1. 用户名
2. 账号
3. 状态
4. 已绑定角色数量
5. 可访问后台范围摘要

角色列表建议展示：

1. 角色名称
2. 角色编码
3. 状态
4. 可访问 Agent 数量
5. 后台菜单访问范围摘要

用户详情中的角色绑定建议展示：

1. 已绑定角色
2. 可选角色
3. 最近更新时间

角色详情中的 Agent 绑定建议展示：

1. Agent 名称
2. Agent 编码
3. 绑定状态
4. 最近更新时间
5. 状态

### 4.7.4 关键按钮和操作说明

1. `新建角色`
作用：新增角色基础信息

2. `绑定角色`
作用：在用户详情中给当前用户分配一个或多个角色

3. `绑定 Agent`
作用：在角色详情中给当前角色分配可访问的 Agent

4. `保存`
作用：保存当前详情中的绑定关系修改

### 4.7.5 页面交互流程

1. 用户进入权限管理页
2. 在 `用户管理` 页签查看用户列表并选择一个用户
3. 打开用户详情，给当前用户绑定一个或多个角色
4. 切换到 `角色管理` 页签并选择一个角色
5. 打开角色详情，给当前角色绑定一个或多个 Agent
6. 保存配置

说明：

1. MVP 阶段不追求复杂的组织架构权限模型
2. 先满足“用户 -> 角色 -> Agent”的访问控制主链路
3. 后台管理权限先由角色级菜单访问范围控制
4. 平台管理员可访问全部管理页和会话页
5. 普通使用者默认只进入会话页，不进入注册中心管理页

### 4.7.6 验收标准

1. 可以新增、查看、编辑用户
2. 可以新增、查看、编辑角色
3. 可以给用户绑定角色
4. 可以给角色绑定 Agent
5. 权限页结构清晰，能区分用户管理和角色管理两类主视图
6. 用户详情和角色详情中的绑定动作边界清楚

---

## 4.8 会话页

### 4.8.1 页面目标

提供 `agent-core` 的最小执行入口，让用户可以选择 Agent、发起会话、查看消息往返。

MVP 规则约定：

1. 一个会话只绑定一个 Agent
2. 会话创建后，本轮会话不允许切换 Agent
3. 从 `Agent 管理页` 进入会话时，默认带入当前 Agent
4. 从首页进入会话时，若未带入 Agent，则必须先选择 Agent
5. 当前会话页只展示轻量执行反馈，不展示完整任务监控面板

### 4.8.2 主要模块区块

1. 左侧会话列表区
2. 中间消息对话区
3. 顶部会话工具栏
4. 底部消息输入区
5. 右侧会话信息抽屉或侧栏

### 4.8.3 主要展示与表单项建议

会话列表项建议展示：

1. 会话标题
2. 关联 Agent 名称
3. 最后消息摘要
4. 更新时间

顶部工具栏建议展示：

1. 当前会话标题
2. 当前 Agent
3. 会话状态

输入区建议字段：

1. `messageContent`

右侧信息区建议展示：

1. 会话 ID
2. Agent 名称
3. 创建时间
4. 最近更新时间
5. 当前状态

### 4.8.4 关键按钮和操作说明

1. `新建会话`
作用：创建新的会话并进入消息区

2. `发送`
作用：发送当前输入消息

3. `清空输入`
作用：清空输入框内容

4. `查看会话信息`
作用：查看当前会话基本信息

5. `重新命名`
作用：修改会话标题

### 4.8.5 页面交互流程

1. 用户进入会话页
2. 点击 `新建会话`
3. 选择或带入默认 Agent
4. 输入问题内容
5. 点击 `发送`
6. 页面展示用户消息
7. 页面展示 Agent 响应
8. 会话列表中更新最后消息和更新时间

说明：

1. MVP 阶段先不强制支持多轮复杂任务轨迹面板
2. 先保证消息往返、会话切换、Agent 选择可用
3. 发送中不允许重复点击 `发送`
4. 发送失败时需提供明确错误提示和重试入口
5. 当前 Agent 不可用时禁止发送，并给出提示

### 4.8.6 验收标准

1. 可以创建会话
2. 可以查看会话列表
3. 可以进入某个会话查看历史消息
4. 可以发送一条消息并收到响应
5. 会话页能展示当前 Agent
6. 空消息不允许发送，并有明确提示
7. 无会话数据时有空状态页
8. 发送失败、超时、无响应时有明确提示
9. 从首页进入且未带入 Agent 时，必须先选择 Agent 才能发送

## 4.9 个人信息 / 退出入口

### 4.9.1 页面目标

为当前登录用户提供最小账户信息查看和退出能力。

### 4.9.2 主要模块区块

1. 顶部头像 / 用户名区域
2. 下拉菜单或小弹层

### 4.9.3 主要展示项建议

1. 用户名
2. 角色名称
3. 当前环境

### 4.9.4 关键按钮和操作说明

1. `个人信息`
作用：查看当前账户基本信息

2. `退出登录`
作用：清除登录态并返回登录页

### 4.9.5 页面交互流程

1. 用户点击右上角用户区域
2. 展开菜单
3. 点击 `个人信息` 或 `退出登录`

### 4.9.6 验收标准

2. 点击 `退出登录` 后可返回登录页
3. 退出后受保护页面不可直接访问

## 5. 页面间交互主流程

## 5.1 登录到资源管理主流程

1. 用户进入登录页
2. 登录成功后进入首页 Dashboard
3. 从首页进入 Agent / Tool / Workflow / Prompt / 权限 管理页
4. 在资源管理页完成新增、编辑、启停或发布操作

## 5.2 Agent 到会话执行主流程

1. 用户进入 Agent 管理页
2. 新建或选择一个可用 Agent
3. 点击 `进入会话`
4. 跳转到会话页并自动带入当前 Agent
5. 用户发送消息
6. 系统返回响应

## 5.3 首页到会话执行主流程

1. 用户登录后进入首页
2. 点击 `开始会话`
3. 进入会话页
4. 先选择 Agent
5. 输入消息并发送

## 5.4 后台访问权限主规则

1. 平台管理员可访问全部注册中心管理页和会话页
2. 运营角色可访问部分资源管理页和会话页
3. 普通使用者默认只访问会话页
4. 未绑定角色的用户登录后不可进入受保护功能页
5. 已绑定角色但未绑定任何 Agent 的用户，可登录但不可发起会话

## 8. MVP 验收标准汇总

## 8.1 登录与权限入口验收

1. 未登录不能直接进入后台核心页面
2. 登录成功后能进入首页
3. 退出登录后需重新登录

## 8.2 注册中心页面验收

1. Agent / Tool / Workflow / Prompt 四个页面都能进入
2. 每个页面都具备最小列表、查询、查看、新增、编辑能力
3. Agent、Tool、Prompt 支持启用 / 停用
4. Workflow 支持查看、编辑、发布、停用

## 8.3 会话页验收

1. 可以创建会话
2. 可以选择或带入 Agent
3. 可以发送消息并看到响应
4. 可以切换历史会话
5. 空状态和异常提示清晰
6. 会话创建后不允许切换当前 Agent

## 8.4 整体体验验收

1. 页面导航清晰，首次进入后台能理解主要入口
2. 主要操作在 3 次点击内可达
3. 列表页、表单页、会话页布局一致，不出现明显风格割裂
4. 常见桌面分辨率下页面不出现明显错位

## 9. 待确认项

以下内容当前建议先按 MVP 默认值推进，后续可由主控 Agent 或你再确认：

1. 首页是否需要展示真实统计数据，还是先用占位数据
2. Workflow 第一版是否需要“节点摘要表格”，还是允许先只录入结构化摘要
3. 登录页是否需要验证码或二次校验
4. Token 过期后是否做静默刷新，还是直接跳登录页
5. 普通使用者是否完全隐藏注册中心菜单，还是展示但不可进入
